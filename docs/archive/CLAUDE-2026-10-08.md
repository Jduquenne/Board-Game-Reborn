# BoardGame Reborn - CLAUDE.md

Refonte architecturale de BoardGame. Même jeu, même gameplay — architecture vanilla JS propre et scalable sans aucune dépendance.

## Lancer le projet

ES modules natifs → serveur HTTP local obligatoire :

```bash
python3 -m http.server 8080
# ou
npx serve .
```

Les assets sont dans `assets/` (local au projet).

## Stack technique

- **Vanilla JS ES2022** — private class fields (`#`), `Object.freeze`, `structuredClone`
- **Zéro dépendance** — pas de jQuery, pas de bundler, pas de npm
- **ES modules natifs** — `import/export` partout

## Architecture — les 4 couches

```
core/        ← infrastructure réutilisable (EventBus, Store, Component, Router)
Engine/      ← logique pure, ZÉRO DOM
Repository/  ← données statiques, instances fraîches à chaque appel
Views/       ← rendu DOM, ZÉRO logique métier
```

## Patterns fondamentaux

### EventBus — liste des événements
| Événement | Émetteur | Payload |
|---|---|---|
| `game:started` | GameEngine | — |
| `turn:changed` | GameEngine | `{ activePlayerIndex }` |
| `trap:triggered` | GameEngine | `{ playerInfo }` |
| `fight:start` | GameEngine | `{ attacker, target }` |
| `fight:attack` | FightEngine | `{ attacker, target, damage }` |
| `fight:defend` | FightEngine | `{ attacker, target }` |
| `fight:round-end` | FightEngine | `{ nextAttacker, nextTarget }` |
| `fight:end` | FightEngine | `{ winner, loser }` |
| `state:changed` | Store | `state` complet |

### Store — shape du state
```js
{
  phase: 'menu' | 'playing' | 'fighting' | 'gameover',
  config: { rows, cols, nbObstacles, nbWeapons, nbBonus, nbTraps },
  cells: Cell[][],      // tableau 2D de plain objects
  players: PlayerInfo[], // [{ player, position: { row, col } }]
  activePlayerIndex: number,
  fight: { attackerIndex, targetIndex } | null,
}
```

### Component — cycle de vie
```js
class MonComposant extends Component {
    render() { return `<div>HTML</div>`; }  // retourne du HTML
    onMount() { /* events DOM, this.listen(...) */ }
    onUnmount() { /* cleanup auto via unmount() */ }
}
```
`listen(event, cb)` enregistre un abonnement EventBus auto-nettoyé au `unmount()`.

### Router
```js
router.register('menu', () => new MenuView('#app')).start();
router.navigate('game'); // unmount du courant + mount du nouveau
```

## Règles à respecter

- **Engine** → jamais de `document`, `querySelector` ou manipulation DOM
- **Views** → jamais de logique métier, jamais d'import de Engine direct sauf GameView/BoardView
- **Models** → fonctions factory pures, jamais de méthodes
- **Repositories** → `findAll()` retourne toujours de nouvelles instances (pas de références partagées)
- **Store** → seule façon de modifier l'état = `store.setState(updater)`

## Règles UI/UX

- **Pas de scroll** — le jeu doit être entièrement contenu dans `100vw / 100vh`, aucun axe scrollable
- **Responsive** — chaque vue s'adapte à la taille de l'écran sans débordement
- **Plateau adaptatif** — la taille des cellules (`--cell-size`) est calculée dynamiquement par `GameView` au démarrage pour que le plateau tienne toujours à l'écran
- `html`, `body`, `#app` → `overflow: hidden` obligatoire
- Les hauteurs fixes (`h150px`, `calc(...)`) sont interdites si elles causent un dépassement du viewport

## Ajouter du contenu

| Tâche | Fichier à modifier |
|---|---|
| Nouveau personnage | `Repository/PlayersRepository.js` → `PLAYER_DATA` |
| Nouvelle arme | `Repository/WeaponsRepository.js` → `WEAPON_DATA` |
| Nouveau bonus | `Repository/BonusRepository.js` → `BONUS_DATA` |
| Nouvelle vue/page | créer `Views/MaVue.js` + `router.register(...)` dans `app.js` |
| Nouvelle option de config | `OptionsView.js` → tableau `OPTIONS` |
| Nouveau type de cellule | `Models/Cell.js` → `DECOR` + `GameEngine.js` + `BoardView.js` |
